# 总方案（详解版）：13 条反馈怎么落地

> 逐条根因与代码证据在 [`user-feedback-analysis-2026-11-15.md`](./user-feedback-analysis-2026-11-15.md)。
> 本文是执行方案，写法偏"讲清楚"，不是清单。
>
> 阅读建议：
> - 只想知道结论 → 直接看 **第 4 节（时间线）**；
> - 想知道为什么这么排 → 看 **第 1、2 节**；
> - 想知道某一项具体怎么改 → 看 **第 3 节**。

---

## 0. 一句话

这 14 个问题里，**大部分不是 14 个独立的 bug，而是 4 个"地基"上的毛病**：

1. 浮层窗口的**上下顺序**和**生死时机**没有约定（宏录制、录屏、锁屏气泡都栽在这）；
2. 跨应用动作（拖拽、模拟点击）在**最不该干重活的时刻干重活**（图片拖不动、宏录制多录一下）；
3. 面板/悬浮球的**尺寸和位置写死在代码里**（太宽、不能离边）；
4. 按钮只会"单击"，**没有第二层操作**（长按切语言、图片单击动作、长按时长）。

所以方案不是"打 14 个补丁"，而是**先把这 4 个地基各补一块，再顺手把 14 个问题收掉**。
好处是：同类问题不会再犯，改动总量更小，而且每一块都能单独发版、单独回滚。

## 1. 三分钟背景（看懂后面全靠这四块）

### 1.1 浮层是"一层层玻璃"，后放的在上面

我们的悬浮球、触钮、宏录制条、录屏 dock、通知气泡，本质都是**系统窗口**（overlay）。
同一类窗口的叠放顺序只看一件事：**谁后添加（`addView`）谁在上面**。

把这想成桌上一摞玻璃：先放一块大的（全屏捕获层），再放一块小的（控制条），
小玻璃在最上面，你点得到它。**但只要你把大玻璃拿起来再放回去，它就跑到最上面了**，
从此手指点小玻璃的位置，先碰到的是大玻璃。

宏录制就是这么坏的（详见 3.1）——而且"拿起来再放回去"在代码里是必要的：
模拟点击时必须先把捕获层摘掉，否则模拟的那一下会被自己接住，形成死循环。

### 1.2 拖拽是"递一张纸条"，纸条上写着内容在哪

系统拖拽（`startDragAndDrop`）本质只做一件事：把一张 `ClipData` 纸条递给落点应用。

- **文字拖拽**：字直接写在纸条上，谁拿到都能看 → 所以文字一直好用。
- **图片拖拽**：纸条上只写了"文件在 `content://...`"这份地址。接收方要能打开这个地址，
  必须有读权限。系统一般会用 `DRAG_FLAG_GLOBAL_URI_READ` 自动授权，但微信/QQ 这类
  只认系统相册（MediaStore），所以我们额外做了一步：**把图片复制一份进系统相册**（叫"镜像"）。

复制文件是重活。现在这步被放在"起拖"的同一口气里同步做，于是：
文件大 → 卡住几十到几百毫秒；复制失败 → 直接 `return false`，拖拽根本没开始（用户看到的就是"没反应"）。

### 1.3 面板大小是"算"出来的，不是"画"出来的

每个面板都有一个布局引擎（`*LayoutEngine`）：输入是密度、屏幕尺寸、贴哪一边、触发区，
输出一个矩形。行高、图标位置、关闭按钮、点击命中区，**全部从这个矩形派生**。

所以"任务切换器太宽"这件事，代码里只有一个地方写死了 `226dp`；
把它改成"从设置读"，整块会等比跟着变，不需要重画。

### 1.4 加开关为什么是最安全的做法

本项目所有行为最终都读同一份设置快照（`AppSettings`）。新增一个开关 = 加一个 key + 给个默认值。

**默认值保持旧行为**，带来两个好处：
- 出问题让用户关掉开关就行，不用紧急发版；
- 新行为可以先给愿意开的人用，稳定了再改默认值（灰度）。

方案里所有"会改变观感"的改动（离边、锁屏气泡、录屏收起 dock、摇杆新模式）都走这条路。

## 2. 四个机制（为什么合并、各自怎么落地）

### 2.1 M1：浮层窗口的"上下顺序 + 生死时机"

**它要解决的三条反馈**

| 反馈 | 表面现象 | 真正的原因 |
|---|---|---|
| #6 宏录制 | 保存那一下被录进宏里 | 捕获层被重新添加后压到了控制条上面（1.1 的玻璃） |
| #7 录屏 | 录屏按钮出现在视频里 | 录屏抓的是整屏，dock 是浮层，必然入镜；而且没有"我该躲一下"的约定 |
| #9 锁屏气泡 | 锁屏收不到气泡，解锁也没了 | 气泡的代码写的是"一熄屏就销毁"，而锁屏必然熄屏；自动关闭的 5 秒倒计时也不会暂停 |

三条看起来无关，其实是同一个问题：**每个浮层各自决定"我什么时候该消失、我该在谁的上面"，
没有统一约定。**

**方案：立三条规则 + 各配一个小工具**

1. **z-order 不变量**：全屏的捕获层/遮罩层，永远不许压在"控制类"窗口（宏录制条、录屏 dock）上面。
   任何"摘掉再装回"的操作之后，必须显式把控制类窗口重新置顶。
   → 工具：`OverlayZOrder.raise(view)`（`core/overlay-host`，就是 remove+add，不是框架）。
2. **锁屏/熄屏声明**：每个常驻浮层必须明确回答三件事——
   熄屏后销毁还是保留？锁屏上要不要显示？自动关闭的倒计时锁屏期间停不停？
   现在这些是各窗口自己注册广播决定的（气泡就是 `ScreenOffDismissReceiver { dismiss() }`）。
   → 工具：一个 `OverlayVisibilityPolicy`（枚举 + 默认值），各窗口按需调用。
3. **自捕获策略**：录屏、截图这类"会拍到自己"的动作，先声明 `HIDE / COLLAPSE / KEEP`。
   → #7 用 `COLLAPSE`（开始 1.2 秒后把 dock 收成不可见，停止入口放通知/磁贴）。

**用户会看到什么变化**
- 宏录制：录几个动作就是几个动作，保存不会多一步；
- 录屏：视频里不再有那个小条；
- 气泡：开了"锁屏显示"后，锁屏能收到，解锁后还在（且重新开始计时）。

**边界（很重要）**：不做窗口管理器、不做运行时排序系统、不新建模块。
三条规则各一个小工具 + 一份 `docs/overlay-window-contract.md`，把这次踩的坑写死。

### 2.2 M2：跨应用动作，重活必须提前做完

**它要解决的两条反馈**

- #13b 图片拖拽没反应：因为"复制到相册"这个重活发生在起拖的那一刻（1.2）；
- #6 多录一下：本质也是"在最敏感的时刻做了额外的事"（摘窗、注入、装回），顺序没管好。

**方案：一条纪律 + 三个动作**

纪律：**在"起拖 / 注入"这种对时序敏感的调用栈里，只允许做 O(1) 的准备工作。**

具体到图片拖拽：
1. 只对**真的需要**镜像的宿主（微信、QQ 这类只认相册的）做复制，其它 App 直接用原地址 + 系统授权；
2. 复制提前做：取词面板里图片一就绪，就在后台把镜像准备好，起拖时只取现成的地址；
3. 失败必须让人看见：起拖失败一律 Toast，不允许"悄悄 return false"；
4. 日志写清失败原因（`mirror` / `flags` / `exception`），用户回传一份日志就能定位。

**用户会看到什么变化**
图片能拖进微信、记事本、相册；拖到不支持图片的地方，松手后面板会恢复（不是消失）。

**为什么不干脆全都镜像？**
因为"全都镜像"就是现在的做法，正是它把主线程卡住了。白名单是最小改动、可控的版本；
名单不够时日志能看出来，再补。

### 2.3 M3：面板和球的"尺寸/位置"从设置读

**它要解决的三条反馈**

- #2 任务切换器太宽：宽度写死 226dp；
- #1 悬浮球想离边：位置只由"显示百分比（0.5–1.0）"决定，球只能贴边；
- #12 区域放大：以后要一个新的浮窗，需要同一套"夹在屏幕内"的算法。

**方案**
1. 面板宽度：布局 host 加一个 `panelWidthDp()`（接口默认 226，不动其它面板），任务切换器先接；
2. 球离边：位置公式本来就能算任意内缩（`left = 屏宽 - 球宽 × 比例`），加一个"内缩 dp"参数即可；
3. 把"矩形夹进屏幕、留边距、贴边判定"抽成一个小函数，放大镜复用。

**为什么不用用户提的"百分比调到 100% 以上"？**
技术上完全可行（公式本来就支持），但"显示百分比"现在的意思是"球露出多少"
（50% = 露一半、100% = 全露但贴边）。如果允许 150%，它同时表示"露出 1.5 个球"——
这个说法对用户是没法解释的。改成一个独立的"距边缘 dp"更直白，也不影响老用户已有的数值。

### 2.4 M4：按钮要有"第二层操作"，长按要有时长

**它要解决的四条反馈**

- #10 翻译按钮长按切语言：现在长按没有任何行为；
- #11 图片单击执行指定功能：现在单击固定"打开看图应用"；
- #5 摇杆松手即点、摇杆保留：属于同一种"手松开之后该发生什么"的变体；
- #8 触钮长按时长不能改：450ms 是硬编码，而项目里其它长按全都可配。

**方案：一条约定 + 两个参数**
- 约定：一个按钮可以有"单击 = 主动作、长按 = 次动作"，**长按必须有反馈**（提示/震动），
  不能做成"只有老用户知道的隐藏功能"；
- 参数：长按时长提成设置；摇杆的"松手动作"提成独立模式。

## 3. 逐项改法

> 每项五段：**你看到的问题 → 现在代码怎么跑 → 改成什么 → 你会看到什么变化 → 怎么验证**。
> 顺序按批次，同批次内按优先级。

### 3.1 批次一（1.66.1）

#### #6 宏录制把"保存"也录进去

- **你看到的问题**：录完宏，最后总多出一个"点保存"的动作。
- **现在代码怎么跑**：捕获层是全屏窗口，控制条是后加的小窗口，一开始条在上面。
  每录完一个动作，为了把这一下"还"给目标 App，捕获层要先摘掉、注入、再装回；
  **装回时它就到了最上面**，从此压住控制条。之后你点保存，手指先被捕获层接住，
  这一下被记成一个步骤；然后程序把这一下注入回去，正好点中保存按钮——
  所以按钮仍然有效，但动作已经进宏了。
- **改成什么**：装回捕获层之后，把控制条重新置顶；再加一道保险：保存前丢弃"落点在控制条范围内"
  的最后一个步骤。顺手删掉两个零引用的旧钩子。
- **你会看到什么变化**：录 3 个动作，保存后就是 3 个；点暂停/停止也不会多出步骤。
- **怎么验证**：端到端录一遍（点两下 → 暂停 → 继续 → 停止 → 保存），数步骤；
  再录一遍滑动，确认目标 App 仍然正常响应（注入没坏）。

#### #13b 图片拖到任何 App 都没反应

- **你看到的问题**：文字能拖进微信，图片怎么拖都没反应。
- **现在代码怎么跑**：见 1.2。图片起拖前要"复制一份进系统相册"，这步是同步的、在主线程、
  而且对**所有** App 都做；复制失败就直接不起拖，失败提示还藏在面板里。
- **改成什么**：只对微信/QQ 这类宿主镜像；图片一就绪就在后台把镜像备好；失败弹 Toast；补日志。
- **你会看到什么变化**：图片能拖进微信、记事本、相册；拖到不支持的地方会回弹恢复面板。
- **怎么验证**：四种落点各试一次（微信/记事本/相册/桌面空白），再试一次"拖起来又放下"。

#### #4 通知滤盒能不能关掉

- **你看到的问题**：滤盒一直记通知，想停。
- **现在代码怎么跑**：收通知的代码里，**记录、过滤、验证码提取是同一段逻辑**，没有开关。
- **改成什么**：加一个"记录通知"开关（默认开）。关掉时**只停记录**，
  过滤规则和验证码提取继续工作——否则用户会以为"关了滤盒，连拦截也坏了"。
- **你会看到什么变化**：关掉后新通知不进列表，但该拦的还拦、验证码还能提。
- **怎么验证**：关掉 → 发几条通知 → 列表不增长；同时验证拦截/提码仍生效；再打开，从当前时刻继续记。

#### #8 触钮长按时长

- **你看到的问题**：触钮（屏幕边缘那条）长按多久算长按，改不了。
- **现在代码怎么跑**：这个是全项目唯一写死的长按（450ms），其它长按（面板、摇杆、轮盘）都能调。
- **改成什么**：加一个设置（200–1200ms，默认 450），手势识别和定时器用同一个值。
- **你会看到什么变化**：默认手感和现在完全一样；想更灵敏可以调到 200。
- **怎么验证**：分别用 200 / 450 / 1200 各试"短按、长按、长按后滑动"。

#### #10 翻译按钮长按切语言

- **你看到的问题**：每次换语言都要进设置。
- **现在代码怎么跑**：翻译按钮只有单击（用设置里的目标语言），长按没行为；
  而"分享"按钮早就有长按了，所以组件本身支持。
- **改成什么**：长按在中⇄英之间切（或按"已下载语言包"轮换），切完给个提示。
- **你会看到什么变化**：长按一次换语言、单击照常翻译，两者不打架。
- **怎么验证**：连按三次长按看是否循环；确认长按没有触发翻译；目标设成"跟随应用"时第一次长按落到具体语言。

#### #13a 亮度回弹（第一步，先稳住 + 留证据）

- **你看到的问题**：亮度条拉上去，一两秒后自己退回原亮度（1.50 正常，1.66 仍复现）。
- **现在代码怎么跑**：写亮度要同时改两个系统值（整数档位 + 0–1 的比例）。1.50 是先写比例、再写档位，
  只走系统设置；1.52 删掉了比例那一半，1.66 又加回来，但顺序和量程算法都变了。
  另外，如果系统开着自动亮度，它会在我们写完之后再算一次，把值推回去。
- **改成什么（这一步）**：自动亮度开着时只写"自动亮度的偏移量"（这是自动模式唯一受支持的通道）；
  写入顺序改回 1.50 的"先比例、后档位"；加一个诊断开关，可以手动切"只走设置 / 只走 shell"，
  让用户一分钟内自证哪条通道在他机器上有效；日志带上写入路径和回读值。
- **你会看到什么变化**：一部分机型立刻好（回到 1.50 的语义）；没好的机型，日志能直接告诉我们原因。
- **怎么验证**：让反馈者拉一次条 → 回传日志（`BrightnessControlHelper` 关键字）→ 按日志定下一步。
  不在没有日志的情况下继续猜。

### 3.2 批次二（1.67）

#### #2 任务切换器宽度可调

- 现状：宽度写死 226dp；行高、图标、关闭按钮、命中区都从这块矩形算，所以改一个数就够。
- 改法：设置里加滑条 180–340dp（默认 226），拖动时实时预览；窄屏/分屏仍然夹在屏内。
- 变化：窄可以窄到不挡内容，宽可以容纳长应用名。
- 验证：三种宽度 × 竖屏/横屏/分屏，看是否出屏、重叠、文字截断。

#### #3 应用内直达补"创建快捷方式"

- 现状：这条路径**从来就没有**这个入口（代码里显式清空了），不是这版弄丢的；
  其它三个挑选器（手势、快速启动器、圆环）都有。
- 改法：把入口接回来，点某个 App 就打开它自己的"创建快捷方式"界面，结果直接加入列表。
- 变化：和手势里选快捷方式的体验一致。
- 验证：创建一次动态快捷方式、一次固定快捷方式；重复创建不出现重复条目。

#### #11 图片区：编辑按钮 / 单击动作 / 全屏缩放旋转

- 现状：图片底栏有"查看/图搜/保存/分享/钉住/暂存"，**没有编辑**；单击图片 = 交给设置里指定的看图应用
  （可以是内置编辑器、某个相册，或者"每次都询问"）；全屏查看器明确不支持缩放旋转。
- 改法：
  1. 底栏加"编辑"，点了直接进内置编辑器（这个能力已经现成，只是没接）；
  2. 单击动作从"只能选看图应用"扩成动作列表（查看/编辑/保存/分享/图搜），复用现有设置；
  3. 全屏查看器加双指缩放、旋转、双击回正、放大后平移夹边。
- 变化：看图时能放大看细节；想"一点就编辑"不用绕。
- 验证：三种手势互不打架；放大到 260% 能拖到四角；旋转 90° 不出屏。

#### #1 悬浮球离边 + 调水平位置

- 现状：位置只有"贴左/贴右/双贴边"和"露出比例（0.5–1.0）"，球只能贴边。
- 改法：新增"距边缘距离（0–48dp，默认 0）"；0 就是现在的行为。
- 变化：球可以离开边缘一点点，不再挡侧滑手势；双贴边模式下会做限幅。
- 验证：0 时与现在完全一致；内缩后取词、面板弹出位置仍然对。

#### #9 侧边气泡锁屏显示

- 现状：气泡"一熄屏就销毁"，而锁屏必然熄屏；默认 5 秒自动关闭，也不会因为锁屏暂停。
- 改法：新增开关（默认关）。开启后：熄屏不销毁、锁屏期间暂停自动关闭、解锁后重新排位置并重新计时；
  如果某些 ROM 会隐藏浮层，就在解锁时重新挂一次。
- 变化：锁屏来消息能看到气泡，解锁后它还在，不会"解锁即消失"。
- 验证：锁屏收消息 → 等 30 秒 → 解锁 → 气泡仍在并重新计时 → 能点开/忽略。

### 3.3 批次三（1.68+）

#### #5 摇杆松手即点、摇杆不消失

- 现状：已有的"松手单击"是**点完就关掉摇杆**，和用户要的"点完留在原地、可以接着拖"是两种模式。
- 改法：新增独立开关（默认关）。松手时在指针处点一下，摇杆留在原地；下次按下继续拖，如此循环。
  同时要明确"怎么退出"（点摇杆外面 / 返回键 / 闲置超时），否则摇杆会一直挂在那。
- 风险：这是全套代码里最复杂的状态机之一（688 行），还牵扯边缘手势交接。
  所以先补单测（按下 → 拖动 → 松手点击 → 摇杆还在 → 再按下 → 再拖动），再改实现。
- 验证：连续循环 10 次不漂移；点外面能关掉；切换 App 不残留。

#### #7 录屏按钮不入镜

- 现状：录屏抓整屏，dock 是浮层，必然入镜；Android 没有"从全屏录制里排除某个窗口"的接口。
- 改法：先补停止入口（通知按钮 + 下拉磁贴），再默认"开始 1.2 秒后收起 dock"，设置里保留"常显"；
  Android 14+ 再补"只录单个应用"模式（这种模式天然不含我们的浮层）。
- 验证：全屏录 10 秒，画面里没有 dock；从通知、磁贴都能停；开启了"常显"的用户行为不变。

#### #12 自定义区域放大

- 现状：没有这个能力。仓库里只有取色器的像素放大，和"区域截图 + OCR"两条不相干的链路。
  另外代码注释已经写死：无障碍截图一次一张、被系统限流，**做不了连续取帧**。
- 改法分两期：
  - 一期（1 周内）：**冻结放大**——截一帧，浮窗里放大显示，可拖动、可调倍率、可手动刷新；
  - 二期：实时放大，必须换成 MediaProjection（或 Shizuku/root 通道），并解决"镜子照到自己"和耗电。
- 先要定的产品参数：放大框跟随手指还是固定、倍率范围、要不要旋转、要不要全屏放大。

## 5. 决策记录（我替你定的默认，都可以推翻）

| 决策 | 我的选择 | 另一个选项 | 为什么这么选 |

## 6. 不做什么（以及为什么）

1. **不做 overlay 架构重构**。仓库已经冻结这块（AGENTS.md 第四节），重构和修 bug 混在一起，
   以后 revert 会把修复一起退掉。M1 只加 3 个小工具 + 1 份文档。
2. **不恢复悬浮球的"自定义坐标"模式**。那套语义已经被"显示百分比"替换，恢复会同时存在两套位置模型；
   用 dp 内缩就能达到用户想要的效果。
3. **1.66.1 里不碰 #5 和 #12**。前者是状态机，后者是新子系统，都不适合放热修包。
4. **不用 `FLAG_SECURE` 解决录屏**。那会让 dock 在视频里变成一块黑，比看到按钮更糟。
5. **没有日志就不继续改亮度**。这条已经改错过一次（1.66 说是修了，用户仍在复现），
   再猜一次只会浪费一个版本。

## 7. 风险与兜底

| 风险 | 兜底 |
|---|---|
| 新行为有人不喜欢 | 全部由设置项驱动、默认旧行为；回滚 = 关开关，不用发版 |
| 白名单不够（某些 App 仍拖不进） | 日志会写明是 mirror 还是 flags 失败；名单后续补，不用改架构 |
| 触钮长按改动影响既有手感 | 默认值就是 450ms，与现在完全一致；只多一个可调项 |
| 锁屏气泡在某些 ROM 不显示 | 先按"熄屏不销毁 + 解锁重挂"兜底；真机验证不过就不默认开 |
| 亮度改了反而影响 ColorOS 用户 | 诊断开关允许切回"只走 shell"；1.66.2 按日志收口 |
| 宏录制 z-order 修复引入新问题 | 改动只有"装回后置顶" + "丢弃落在条内的末尾步骤"，两者都有单测和端到端验证 |
